Transformer 架构与注意力机制

发表于2026-06-10|更新于2026-11-05|AI Infrastructure
|浏览量:

Embedding 查表为每个 token 提供初始向量，但同一个 token 在不同句子里仍会取到同一行参数。Transformer 通过 Attention 聚合上下文，再用前馈网络做非线性变换，形成与当前语境相关的表示。

本文先展开单层计算，再讨论多头结构、KV Cache 与 FlashAttention。示例以因果语言模型为主，每个位置只能访问自身及此前的 token。

一、Self-Attention 机制

给定一个长度为 NNN 的 token 序列，每个 token 对应一个 ddd 维向量。要让 tokeni_ii​ 的表示融合其他 token 的信息，最直接的想法是加权平均——权重由 tokeni_ii​ 和 tokenj_jj​ 的相似度决定。这就是 Self-Attention 的起点。

QKV 注意力分数

输入矩阵 X∈RN×dX \in \mathbb{R}^{N \times d}X∈RN×d（NNN 个 token，每个 ddd 维），通过三个可学习的投影矩阵得到：

Q=XWQ,K=XWK,V=XWVQ = XW_Q, \quad K = XW_K, \quad V = XW_VQ=XWQ​,K=XWK​,V=XWV​

其中 WQ,WK,WV∈Rd×dkW_Q, W_K, W_V \in \mathbb{R}^{d \times d_k}WQ​,WK​,WV​∈Rd×dk​。

注意力输出定义为：

Attention(Q,K,V)=softmax(QKTdk)V\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)VAttention(Q,K,V)=softmax(dk​​QKT​)V

逐项拆解：

  • QKT∈RN×NQK^T \in \mathbb{R}^{N \times N}QKT∈RN×N：注意力分数矩阵。(i,j)(i, j)(i,j) 位置的值 = tokeni_ii​ 对 tokenj_jj​ 的关注程度。QQQ 决定"我在找什么"，KKK 决定"我有什么"，点积高说明匹配度高。
  • dk\sqrt{d_k}dk​​：缩放因子。当 dkd_kdk​ 较大时，点积的方差 ∝dk\propto d_k∝dk​，导致 softmax 输出趋近 one-hot（只有一个 token 获得全部权重）。除以 dk\sqrt{d_k}dk​​ 使方差回到 O(1)\mathcal{O}(1)O(1)，梯度更平滑。
  • softmax\text{softmax}softmax：将分数归一化为概率分布，每行和为 1。
  • 乘以 VVV：按注意力权重加权聚合 value 向量。注意力高的 token 的 VVV 在输出中占更大比重。

输出是一个下三角的 5×55\times55×5 权重矩阵，每行和为 1。第 0 个位置只能访问自身；后续位置可以对此前各位置分配权重。随机投影尚未学到语言关系，不能据此解释具体词语之间的依赖。

Causal Mask

因果 decoder-only 模型（如 Qwen3）在训练时只能看到当前 token 和之前的 token。mask 的做法是把 softmax 之前分数矩阵的上三角填为 −∞-\infty−∞：

maskij={0j≤i−∞j>i\text{mask}_{ij} = \begin{cases} 0 & j \leq i \\ -\infty & j > i \end{cases}maskij​={0−∞​j≤ij>i​

softmax(−∞-\infty−∞) = 0，因此未来位置的注意力权重全部为 0。

复杂度

QKTQK^TQKT 是 N×NN\times NN×N 的矩阵。仅考虑一个样本的一个 head，序列长度 4096 时有：

4096×4096=16,777,216 元素4096 \times 4096 = 16,777,216 \text{ 元素}4096×4096=16,777,216 元素

该矩阵用 FP32 存储占 64 MiB，FP16 占 32 MiB。批量与 head 数还要继续乘入。朴素 Attention 的分数矩阵空间复杂度为 O(N2)O(N^2)O(N2)，计算复杂度为 O(N2dk)O(N^2d_k)O(N2dk​)；融合内核可以避免保存完整分数矩阵，但不因此消除全注意力的平方计算量。

Self-Attention 让每个 token 能"看到"前面的所有 token。但一套 QKV 只提供单一的注意力模式——它把所有上下文关系压缩到同一组权重里。

二、Multi-Head Attention 与前馈网络

Multi-Head Attention

把 ddd 维拆成 hhh 个 head，每个 head 独立计算一组 QKV，然后拼接：

headi=Attention(Qi,Ki,Vi)\text{head}_i = \text{Attention}(Q_i, K_i, V_i)headi​=Attention(Qi​,Ki​,Vi​)
MultiHead(X)=Concat(head1,…,headh)WO\text{MultiHead}(X) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h) W_OMultiHead(X)=Concat(head1​,…,headh​)WO​

其中每个 head 的 WQi,WKi,WVi∈Rd×dkW_Q^i, W_K^i, W_V^i \in \mathbb{R}^{d \times d_k}WQi​,WKi​,WVi​∈Rd×dk​，dk=d/hd_k = d / hdk​=d/h。

不同 head 可以学习不同类型的上下文关系。训练后的模型中，某些 head 倾向于关注语法关系（主谓一致、时态匹配），某些关注语义关系（指代消解、同义替换），某些关注局部模式（相邻词的搭配）。

以 Qwen3-8B 为例，隐藏维度为 4096，Q head 数为 32，每个 head 的维度是 128；它使用 8 个 KV head，后面会说明这种分组方式。不同架构可以选择其他 head 维度，具体取决于表示能力与内核效率的取舍。

SwiGLU 前馈网络

Attention 聚合可见位置的信息，FFN 随后对每个位置的表示做非线性变换。它在 token 之间共享参数，但逐位置执行。

Qwen3 等模型的 FFN 使用 SwiGLU：

SwiGLU(x)=(Swish(xW1)⊙(xW3))W2\text{SwiGLU}(x) = \big(\text{Swish}(xW_1) \odot (xW_3)\big)W_2SwiGLU(x)=(Swish(xW1​)⊙(xW3​))W2​

其中 Swish(z)=z⋅σ(βz)\text{Swish}(z) = z \cdot \sigma(\beta z)Swish(z)=z⋅σ(βz)，β\betaβ 通常取 1。SwiGLU 有三组权重（W1,W2,W3W_1, W_2, W_3W1​,W2​,W3​），相比传统 ReLU FFN 多了 W3W_3W3​ 作为门控支路。

Qwen3-8B 的 FFN 中间维度为 12288。忽略 bias 与 Norm 后，单层主要参数可计算为：

  • Q/O 投影：2×4096×40962\times4096\times40962×4096×4096；
  • K/V 投影：2×4096×(8×128)2\times4096\times(8\times128)2×4096×(8×128)；
  • SwiGLU FFN：3×4096×122883\times4096\times122883×4096×12288。

Attention 投影合计约 41.94M 参数，FFN 约 150.99M，占这两部分之和的约 78.3%。这里使用的是 GQA 配置，不能沿用四个等宽投影的 MHA 参数公式。Qwen3-8B 官方配置

自回归推理通常缓存各层历史位置的 K/V，避免每步重做历史前向。以下比较统一注明单层与全部层，具体显存还要乘请求长度和活跃请求数。

三、KV Cache 的架构差异

MHA、MQA 与 GQA

MHA 为各个 Q head 配置独立的 K/V head。MQA 让所有 Q head 共享一组 K/V，GQA 则让多组 Q head 分别共享 K/V。对相同的层数与 head dimension，缓存大小正比于 KV head 数。

用 32 个 Q head、head dimension 128、BF16 缓存作单层对照：

结构 KV head 数 单层每 token 缓存
MHA 32 16 KiB
MQA 1 0.5 KiB
GQA 8 4 KiB

这些是同一组假设维度下的存储比较，不代表同一个检查点可以直接切换结构。共享程度会影响表示能力，需要结合训练与评测判断，不能给出固定的质量排序。

Qwen3-8B 使用表中 GQA 的维度并有 36 层，全部层每 token 的 BF16 KV 为 36×4=14436\times4=14436×4=144 KiB。单条 32768-token 请求需要 4.5 GiB。只有注明层数，单层 4 KiB 才能转换为整模型占用。

MLA：缓存联合压缩表示

DeepSeek-V2 提出的 MLA 从当前隐藏状态生成 K/V 的联合低维表示。可把内容部分概括为：

ctKV=WDKVht,ktC=WUKctKV,vtC=WUVctKVc_t^{KV}=W^{DKV}h_t,\qquad k_t^C=W^{UK}c_t^{KV},\qquad v_t^C=W^{UV}c_t^{KV}ctKV​=WDKVht​,ktC​=WUKctKV​,vtC​=WUVctKV​

推理保留低维的 ctKVc_t^{KV}ctKV​，并结合权重吸收等计算变换，减少存储和搬运完整 K/V 的需要。位置编码部分采用解耦设计，还要保存相应的 key 状态，因此缓存不只有一个低维向量。

MLA 的缓存应按联合压缩表示与位置相关状态分别计数。与 MHA/GQA 比较时，需统一层数、缓存精度和上下文长度。

架构压缩主要减少 KV 的长期存储。Prefill 中的注意力中间结果还需要另行优化，FlashAttention 处理的是这部分计算与 HBM 访问。

四、FlashAttention 与 IO 优化

HBM 与片上存储

Q/K/V 和输出通常存放在 HBM；计算过程中，GPU 用寄存器和各 SM 的共享内存保留小块中间结果。片上存储容量有限，并按计算单元组织，不能把全芯片缓存容量当成单个线程块可以使用的一块空间。

朴素实现先生成分数矩阵，写回 HBM，再读取它做 softmax，最后与 V 相乘。以单 head、4096 长度为例，FP16 分数矩阵已有 32 MiB，多次读写会增加 HBM 流量。

大中间结果的搬运可能成为瓶颈；具体占比仍取决于长度、批量、精度和内核，不能概括为所有场景下“GPU 大部分时间都在等数据”。

FlashAttention 的做法

FlashAttention 将注意力计算分块，避免把完整分数矩阵与权重矩阵写入 HBM。

Tiling： 将 Q/K/V 分成内核可以处理的小块，局部分数与输出累积保留在片上。tile 大小受共享内存、寄存器、head dimension 和并行方式约束。

Online Softmax： 逐块维护最大值、归一化和与加权输出，读入新块时重新缩放已有累积结果，从而计算与整体 softmax 等价的结果。

Recomputation： 训练反向时，根据输入和保存的归一化统计重新计算局部注意力，减少保存大中间矩阵的需求。它用部分额外计算换取更少的存储与 HBM 访问。

FlashAttention 和 FlashAttention-2 分别讨论了 IO 优化与进一步的并行改进。加速比依赖对照实现、硬件和序列规格；它避免平方大小的中间存储，但全注意力计算仍随序列长度平方增长。
